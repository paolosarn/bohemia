The mods folder

MODS. A design, not built. The demo never touches it. Every line under PROVED ran against the real data files.

THE FOLDER

records/target/mods/
  index.json          ["knife-harder"]   the on/off list
  knife-harder/
    manifest.json
    weapons.json      named like the file it patches

A WHOLE MOD (make the knife hit harder)

{ "id": "knife-harder", "name": "Knife Harder", "version": "1.0.0", "schema": 1 }

weapons.json
{ "rows": { "knife": { "damage_min": 20, "damage_max": 30 } } }

THE RULES

Base first, then mods in list order. A later mod wins and says so.
A row is changed by its id. Only the fields named change.
A wrong value skips that whole row change, never half of it.
A broken mod is named and skipped. The game never crashes.

PROVED (11 of 11)

11 / 11
PASSAn empty mods folder changes nothing
PASSA missing mods folder changes nothing
PASSA mod wrong in every way changes nothing, and each fault is named
PASSA good mod changes exactly what it says (the knife, 20 to 30); every other row stays
PASSA mod can add a row (a Moon Blade): it adds exactly one
PASSTwo mods fight over a field: the later wins and it says so
PASSNothing the player plays asks for a mods folder
It checks the type of a number, not how big it is. A knife that hits for minus 5 would load. That needs a range in the data files, which is the numbers chat's table.
