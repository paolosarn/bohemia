================================================================================
ONE SET OF CONTROLS
================================================================================

faceControlsUI(host, dev) is the workbench's own body. The creator calls it with
dev=false, which drops the calibration pad and the "EXPORT THIS FACE (to Claude)"
button -- both about MAKING the game rather than playing it.

FACE_REBUILD names whichever surface is showing the controls. Before this, every
refresh inside them called buildFaceEditor() BY NAME, hard-wiring them to the dev
panel's own div, so a second surface would have HAD to be a second implementation.

A second face editor is exactly how the portrait and the body became different
people on 8/27. Not twice.

================================================================================
THREE THINGS THIS COST, AND ALL THREE GENERALISE
================================================================================

1. ANYTHING A PATCH TOOL OWNS MUST BE EDITED AT ITS SOURCE.

   Story.prototype.hold/resume were written straight into the alpha. They worked.
   Then tools/bohemia_cutscene_tab_patch.py -- which OWNS that script block and
   inlines engine/bohemia_story_surface.js VERBATIM -- ran, and wiped them.

   The failure was silent and FLATTERING: the creator still appeared, the DONE
   button still worked, the portrait still painted, and the scene played on
   HAPPILY BEHIND THE CREATOR with every other check green. Only a probe that
   asked "is the beat clock actually stopped" caught it.

   Fixed in the engine file. The gate now asserts the capability lives there.

2. THE SCENE THE GAME OPENS WITH HAS THREE COPIES AND ONLY ONE IS PLAYED.

     records/BOHEMIA_SCENE_ACT1_COLD_OPEN.json    the canon source
     var BOHEMIA_COLD_OPEN (alpha)                read by coldopen_gate.js ONLY
     BOHEMIA_CUTSCENES[..].scene (alpha)          the ONLY one openScene() reads

   I edited the middle one by hand. Every report said success. The game did not
   change by one pixel, because nothing playing reads that variable.

   The patch tool writes all three from the record, which is the correct pipeline.
   The trap is that hand-editing any single copy LOOKS EXACTLY LIKE WORKING.
   A DUPLICATE NOTHING READS IS WORSE THAN NO DUPLICATE: it is where your fix goes
   to die.

3. A GUARD BELONGS INSIDE THE THING IT GUARDS.

   "Ask once per device" was written into the beat hook -- a property of ONE
   CALLER rather than of the function. The gate called openBecome() directly and
   it re-opened over somebody who had already answered. Moved inside. A guard
   outside the function it guards holds only until somebody else calls in.

AND ONE MORE, ON LOOKING
================================================================================

The first screenshot came back BLACK while every probe reported success. Cause:
the probe hid the front splash with display:none instead of tapping it, which
leaves #app display:none, so the whole creator rendered into a hidden tree --
this file's own documented lie (a flex child of a display:none parent still
computes display:flex), which had already cost a whole cutscene playing inside a
hidden panel on 8/25.

TAP THE SPLASH THE WAY A FINGER TAPS IT. Fixed in the probe and in the gate.

LOOKING ALSO CAUGHT THE PURPLE. The workbench's sliders are lilac (#b39ddb) and
PURPLE RESERVATION gives purple to the Amalgamation alone. Tolerable on a dev
bench; not on a screen the player sees. The accent is a CSS VARIABLE now
(--faceAcc), not an override -- the first cut matched on the inline style TEXT
and missed, because cssText re-serialises #b39ddb as rgb(179, 157, 219). Not one
dev panel changed.

AND A FACE THAT FORGETS IS NOT A FACE
================================================================================

pface lived in memory only. That was survivable while the only person who ever
touched it was Paolo on a bench he keeps open. It stopped being survivable the
moment a PLAYER met the creator in the opening: build a head, lock the phone,
come back tomorrow, and you are Punk again -- WITH NO WAY BACK, because the
creator only ever asks once.

Same class as the VOTE tab holding three weeks of verdicts in `var V={}` (fixed
8/28). Second time this month a surface has lost somebody's work. A CHOICE THAT
EVAPORATES IS NOT A CHOICE, and the second time it happens they stop trusting
the surface.

Now: THIS IS ME writes the face, and so does every control on the bench, so his
own work survives a reload too. IT FAILS SAFE IN BOTH DIRECTIONS -- nothing
stored, storage refused (a private window), or a corrupt blob, and the approved
PUNK face is what renders, exactly as before. The load MERGES onto PUNK rather
than replacing it, so a save from an older build cannot render a head with a hole
in it, and it only ever restores fields PUNK already has, so it cannot inject a
shape the clamps have never seen.

MUTATION TESTED, because a check that reads what you handed it is not a check:
stubbing faceLoad to return false turns the reload check red and names the eye
gap that moved (8 before, 6 after).
