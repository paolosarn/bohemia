================================================================================
TWO THINGS I GOT WRONG, BOTH CAUGHT BY DRIVING IT RATHER THAN READING IT
================================================================================
1. THE AGEING MODEL WAS WRONG AND IT READ FINE. The first cut added a flat three
   rungs at a fold, which made MARCO -- a teen -- an ELDER after thirty years. A
   teen plus thirty is forty-five, which is an adult. A LADDER POSITION IS NOT A
   NUMBER OF YEARS. It now uses the ordinary age bands (child under 13, teen
   13-17, adult 18-64, elder 65+) with the band midpoint as the estimator when
   all you have is a word, which is all the cast gives. Across two folds now:
   MARCO teen -> 45 adult -> 75 elder; a newborn -> 30 adult -> 60 adult; RAY
   adult -> 71 elder.
2. THE BUTTON WAS BOUND TO THE WRONG CARD AND COULD NEVER HAVE WORKED. The first
   cut bound the Marry handler in ctDraw, with the person card's other buttons.
   The row renders on the STANDING card, which is a different element built by a
   different function. Nothing threw, nothing logged, and the button simply did
   nothing. Only pressing it on the real surface found it. That is the entire
   argument for VERIFY ON THE REAL SURFACE being a law and not advice.

THE ONE RULE, TWICE, PROVEN. The played game cannot import a handoff bundle, so
heirOf is unavoidably a second copy of the heir rule -- and two places holding
one rule is the bug this repo keeps paying for. So it is not left to luck: the
gate runs heirOf and the bundle's selectHeir over 600 randomised families and
seeds and fails on a single disagreement. 0 disagreements, and the sweep really
exercises all three answers (435 child, 101 sibling's child, 64 nobody) so it is
not 600 easy cases.
